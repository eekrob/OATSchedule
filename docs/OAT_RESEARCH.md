# Исследование oat.ru

Дата проверки: 6 октября 2026 г. (страницы показывали расписание на 7 октября).

## Страницы и реальная навигация

| Назначение | Endpoint |
|---|---|
| Старт расписания | `https://www.oat.ru/timetable/Classes` |
| Категории групп | `https://www.oat.ru/timetable/groups/{slug}` |
| Расписание группы | `https://www.oat.ru/timetable/timetable/{slug}/{URL-encoded group}` |
| Список изменений | `https://www.oat.ru/timetable/ClassesChanges` |
| Изменения корпуса | `https://www.oat.ru/timetable/Changes/{b1…b4}` |
| Изменения корпуса за день | `https://www.oat.ru/timetable/Changes/{b1…b4}/{dd.MM.yyyy}` |

## Формат данных

Страницы дают содержательные HTML таблицы с сервера. В доступном браузере контент присутствовал сразу в документе: список корпусов, групп, недель и табличные занятия/изменения; признаков обязательного клиентского JSON для этих экранов не обнаружено. Четыре основных раздела перечислены ссылками: корпуса 1–4 (Ленина 24, Богдана Хмельницкого 281а, Космический 14а, Волховстроя 5). В каждом разделе `/groups/{slug}` строки таблицы групп ведут по ссылкам `/timetable/{slug}/{group}`. Группы имеют разные курсы и буквенно-цифровые имена (например, ПР116, ПР215, КС314).

Страница расписания содержит две таблицы с заголовками дней `Понедельник-1` … `Воскресенье-1` и `…-2`: это первая и вторая учебные недели. В колонке времени находятся точные начала и окончания пар; пример: 08:00–09:30, 09:40–11:10, 11:30–13:00, 13:40–15:10. Некоторые ячейки содержат несколько записей и номера подгрупп. День может быть пустым.

`ClassesChanges` показывает четыре корпуса. На странице корпуса есть ссылки на даты в формате `dd.MM.yyyy`, текущая учебная неделя, таблица и режим звонков. Заголовки таблицы изменений: курс, группа, номер пары, аудитория, дисциплина, преподаватель, причина, затем поля новой пары/аудитории/дисциплины/преподавателя. Примеры причин на проверенной странице: `пр/н`, `бол`, `отпуск`; аудитория `отмена` означает отмену пары. Замена представлена структурированной строкой «до/после».

## Реализация и ограничения исследования

Приложение использует URLSession и SwiftSoup: категории и группы собираются по семантическим ссылкам, расписание и изменения — из таблиц с заголовками, а не по позициям элементов. Список изменений проверяется для всех дат, доступных на странице корпуса. Сравниваются нормализованные записи, не сырой HTML; первая полученная версия является baseline.

Исследование выполнено по загруженным страницам и их видимому DOM. В этой среде нельзя было просмотреть вкладку Network/сырой ответ и заголовки кодировки; поэтому отсутствие XHR/JSON API не доказано на уровне сетевой трассы. В реализации выбран server-rendered HTML, который фактически содержит все перечисленные данные. SwiftSoup декодирует Unicode/HTML entities; следует перепроверить кодировку ответа на Mac/Xcode устройстве. Возможные изменения HTML/ограничение частоты запросов остаются риском; parser валидирует ожидаемые заголовки перед обновлением кеша.

Частый фоновой мониторинг на одном iPhone ненадёжен из-за ограничений iOS. Фоновое обновление в приложении best-effort; для оперативных уведомлений потребуется размещённый backend, хранилище подписок и APNs ключ. В этой поставке нет учётных данных и настроенного сервера, поэтому push backend не включён.
